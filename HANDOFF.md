## Architecture notes for whoever resumes

- Stack: React 19 + Vite + TS + Tailwind v4, Context+useReducer, localStorage key `budgetbold-data`, schema version **4** (migration in `src/context/budget-schema.ts`).
- Demo model: `utils/demo.ts` owns the demo keys + generator; cross-component sync uses a `budgetbold-demo-changed` window event (same pattern as the lock event). The persist effect re-reads the demo flag each run, so flag flips and RESTORE_STATE dispatches always land in the right store. Demo transactions deliberately reuse exact template amounts for salary/rent/streaming/fibre so auto-post dedupe stays consistent.
- Edit model: `UPDATE_TRANSACTION` is a move-aware upsert (old month out → new month in, keyed off `transaction.date`); the quick-add modal is the single add+edit surface via `editingTx` in UIContext — any new list surface should call `openEditTransaction(monthKey(y,m), tx)` and needs no modal wiring beyond Layout's existing pass-through.
- ESLint-enforced convention: context definition files (`*-context.ts`) only hold `createContext`; provider files only components; non-component exports live in plain `.ts` modules (that's why budget-schema exists).
- Money model: balance = income − expense − saved; goal progress derived from ledger via `utils/goals.ts`.
- Lock model: PIN hash lives under `budgetbold-lock`, deliberately outside `BudgetState` so backups/restore/currency never touch it; LockGate sits inside ThemeProvider but wraps BrowserRouter, so nothing (providers, routes, data) mounts while locked. PinEntry resets via parent-supplied React `key` + initial `shake` prop — no setState-in-effect (react-hooks v7 lint forbids it).
- List/a11y model: `ShowMoreList` resets its page count by comparing the memoized items array identity during render (documented "adjust state when props change" pattern — keep item arrays `useMemo`-stable at call sites). `SwipeableRow` is touch-only (mouse unaffected), direction-locks against vertical scroll, and keeps inline delete buttons for desktop/keyboard paths.
- No code comments unless requested. Tailwind arbitrary values need brackets (`text-[10px]`).
- Design tokens: `rounded-card/input/button/icon`, `bg-primary hover:bg-primary-dark`, `text-primary dark:text-primary-light`, `dark:bg-surface-dark`.
- Bundle reality check: index chunk ≈ 320KB / gzip 100KB, Reports chunk ≈ 275KB / gzip 83KB, MonthlyComparisonChart ≈ 350KB / gzip 104KB. The old "~258KB gzip 82KB main bundle" note in earlier handoffs actually described the Reports chunk — numbers were stale, not a regression.
- Accounts model: schema v5 invariant — every transaction ends up tagged to an account (`backfillAccounts()` runs on every load, guarantees a Default account exists and sweeps strays, so "Unassigned" is transient within a session only). Per-account balance = opening + income − (expense + savings) over tagged txs; global metrics intentionally unchanged. Transfers will need a linked-pair vs new-type decision — do NOT reuse savings semantics.
